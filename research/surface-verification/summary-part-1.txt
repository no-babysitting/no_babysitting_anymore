##### research_ch02-04
Ánh xạ tính năng cho 3 chương 02-context, 03-plan, 04-memory, ưu tiên các surface app. Tất cả nguồn đã được tải trực tiếp ngày 2026-11-06.

Kết luận chính:
1. Claude Code không chỉ là công cụ lập trình. Trang common-workflows (https://code.claude.com/docs/en/common-workflows.md) nêu rõ nó chạy trong bất kỳ thư mục nào, kể cả notes vault hay thư mục tài liệu không phải code.
2. Desktop Code tab và claude.ai/code đã đủ cho phần lớn tính năng ngữ cảnh và lập kế hoạch: /context, /compact, Plan, resume, @-mention, đính kèm file.
3. Khoảng trống lớn nhất cho người không phải dev là Cowork. Theo trang hỗ trợ (https://support.claude.com/en/articles/13345190-getting-started-with-cowork), Cowork có chế độ Manual, Auto, Skip chứ không có Plan mode. Tài liệu đã đọc không ghi /compact, /clear, rewind hay /memory cho Cowork. Thay thế có sẵn là Instructions và Memory theo từng project.
4. Rewind, /clear và /memory được tài liệu đầy đủ cho CLI. Desktop chưa có tài liệu rõ, nên ghi "unknown" thay vì suy đoán.
5. Gói dịch vụ: cloud sessions cần Pro, Max, Ultra, Team hoặc Enterprise có premium seats. Cowork cần gói trả phí.
6. Một số tính năng còn beta: Cowork trên Linux (beta), Cowork cho Team trên web và mobile (beta).

- Plan mode [03-plan] D:yes W:yes Cw:no M:yes CLI:yes
  APP: Desktop: open the mode selector under the prompt box and choose Plan. It applies to this session only. Cmd+Shift+M (Ctrl+Shift+M on Windows) opens the mode menu. Shift+Tab does not cycle modes in Desktop. claude.ai/code: choose Plan from the mode dropdown when creating a task or during a session. Mobile: tap +, then Permission, then Plan. Cowork offers Manual, Auto and Skip instead, per the Cowork help page.
  CLI: Press Shift+Tab until the status bar shows "⏸ plan mode on", or prefix a prompt with /plan [description]. Start with claude --permission-mode plan. When the plan is ready, options include "Yes, and use auto mode" (or "Yes, auto-accept edits" if auto is unavailable), "Yes, manually approve edits" and "No, keep planning". Ctrl+G edits the plan in your text editor first.
  NC: Start a weekly market report in Plan mode. Claude lists the sources and outline and writes nothing until you approve.
  NOTE: Plan mode blocks edits until approval. The approved plan is re-injected from disk after compaction. Cowork has no documented plan mode.
  SRC: https://code.claude.com/docs/en/permission-modes.md https://code.claude.com/docs/en/desktop.md https://code.claude.com/docs/en/claude-code-on-the-web.md https://code.claude.com/docs/en/mobile.md https://code.claude.com/docs/en/context-window.md https://support.claude.com/en/articles/13345190-getting-started-with-cowork

- CLAUDE.md project memory and /init [04-memory] D:partial W:unknown Cw:partial M:unknown CLI:yes
  APP: Desktop: CLAUDE.md files in the project are read by both the CLI and Desktop. No creation or editing UI is documented. - .claude/rules [04-memory] D:unknown W:unknown Cw:unknown M:unknown CLI:yes
  APP: Not documented for any app surface in the pages read. Rules are files in the project's .claude/rules/ folder.

- Auto memory [04-memory] D:unknown W:unknown Cw:partial M:unknown CLI:yes
  APP: Cowork has project memory, not auto memory. Turn it off for a project in the project's Memory section with the Use account memory toggle. The Memory toggle in the + menu, before the first message, disables memory for one task, and it cannot be changed after the task starts. Auto memory in Desktop and cloud sessions is not documented. Auto memory is machine-local and is not shared with cloud environments.
  CLI: On by default in local sessions. Toggle it in /memory, which saves autoMemoryEnabled to ~/.claude/settings.json. Disable with CLAUDE_CODE_DISABLE_AUTO_MEMORY=1. Files live in ~/.claude/projects/<project>/memory/ with a MEMORY.md index; the first 200 lines or 25KB load every session. Asking Claude to remember something saves it to auto memory.
  NC: Claude remembers a client's preferred report format across weekly runs. Check MEMORY.md to correct it.
  NOTE: Cowork memory and Claude Code auto memory are separate systems. Do not conflate them.
  SRC: https://code.claude.com/docs/en/memory.md https://support.claude.com/en/articles/14116274-organize-your-tasks-with-claude-cowork https://support.claude.com/en/articles/13345190-getting-started-with-cowork

##### research_ch08-09
Feature map for chapters 08-orchestration and 09-scale, researched 2026-11-06 from code.claude.com/docs, claude.com/docs and the Cowork changelog. Cells marked "unknown" are not stated in the pages I fetched; I did not guess them.

Key findings for the app-first positioning:
- The docs back the non-dev framing. The Cowork overview says Cowork "uses the same agentic architecture that powers Claude Code, accessible within Claude Desktop without opening the terminal" (https://claude.com/docs/cowork/overview.md). The Claude Tag overview says team work in shared channels is Claude Tag, and personal work on your own files is Cowork or Claude Code (https://claude.com/docs/claude-tag/overview.md).
- Items that work well from the app side: dynamic workflows (CLI, Desktop and IDE per the docs), Desktop parallel sessions with the Worktree toggle, Desktop scheduled tasks (Code tab > Scheduled), /goal in the Desktop app, Remote Control to phone (Claude app and claude.ai/code), Cowork scheduled tasks, and Claude Tag routines in Slack (Team and Enterprise).
- CLI-only items: claude agents / --bg, /loop, claude --worktree, claude remote-control, /install-github-app, and claude --cloud.
- Naming clarifications: "teleport" is not phone access. claude --teleport and /teleport pull a cloud session into the terminal, one way. Phone access is Remote Control. Routines were renamed to "scheduled tasks" (cloud), and the Desktop app may still show "Routines" on older builds. The legacy "Claude in Slack" bot was retired for Claude Tag-connected channels effective October 5, 2026.
- Status: agent view is in research preview. Cloud scheduled tasks are in research preview. Agent teams are experimental and off by default. Claude Tag is public beta. Workflows show no preview label in the docs.
- Plan gates: workflows need a paid plan (Pro needs the Dynamic workflows toggle in /config). Cloud sessions and scheduled tasks need Pro, Max, Ultra, Team or Enterprise. Remote Control needs the same plans, with no API-key auth. Claude Tag needs Team or Enterprise. Dispatch needs Pro, Max or Ultra. The docs do not state plan requirements for agent teams, agent view, /goal, /loop, or Desktop scheduled tasks.

- (5) /loop scheduled tasks (session-scoped, local) [09-scale] D:unknown W:partial Cw:no M:unknown CLI:yes
